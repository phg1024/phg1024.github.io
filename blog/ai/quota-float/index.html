I Got Tired of Checking My Token Quota, So I Made It Impossible Not to See

Oct 27, 2026

Most of my coding now happens with two agents open: Codex on a ChatGPT plan and Claude Code on a Claude plan. Both plans are generous. Both also have limits, and the limits come in layers: a rolling 5-hour window, a weekly window, and on the Claude side a separate weekly allowance per model. Each one resets on its own schedule.

So I developed a tic. Before handing an agent anything big, and again partway through, I'd stop and check how much was left: /usage in Claude Code, the status screen in Codex. Then I'd go back to work, half-remember the number, and check again a little later.

None of this is hard. It is just constant, and it is exactly the kind of interruption that breaks a train of thought: you leave the problem to go look up a number, and the number isn't even what you were thinking about. After enough of that, I stopped asking how to check faster and started asking why I was checking at all. The information should simply be there, the way the battery percentage is.

That's Quota Float.

What it does

It is a small macOS app with two faces.

A floating panel shows every window for both services — 5-hour, weekly, per-model — as a percentage remaining, with a bar and the reset time in local time. It floats above other windows on every Space, so it is visible over the editor, the terminal and the browser. Drag the title to put it wherever it bothers you least; the position is remembered. When I want the screen back, the hide button puts it away.

A menu-bar gauge is the at-a-glance version. For each service (✦ for Codex, ✱ for Claude) it draws two stacked bars, 5-hour on top and weekly below, next to the lower of the two percentages — the one that will stop me first. Bars turn orange at 25% left and red at 10%. Hovering or opening the menu gives the full text.

Two rules I cared about more than any feature:

  • Never guess. If a value isn't available, it is shown as unavailable. If a refresh fails, the last good numbers stay up with a stale-data notice instead of disappearing or being replaced by something plausible. A quota display that is confidently wrong is worse than none, because you stop checking.
  • Never touch credentials. More on that next, because it shaped the whole design.

Codex refreshes every minute and Claude every five minutes, plus on demand and after waking from sleep.

Getting the numbers without holding any keys

The obvious way to build this is to take an API token and call the services directly. I didn't want that. It means storing secrets in yet another app, and plan quota isn't even attached to API keys — it belongs to the signed-in plan account.

Both services already ship a CLI that manages its own sign-in. So Quota Float doesn't sign in to anything. It starts the CLI, asks it for the numbers, and reads the answer:

  • Codex: it starts codex app-server, which speaks JSON-RPC over stdio, sends initialize, and calls the documented account/rateLimits/read method. The response carries each bucket's used percentage, window length and reset time.
  • Claude: it starts claude -p in stream-JSON mode and sends a single get_usage control request — the same data behind /usage. No prompt and no user message is ever sent, so no model turn starts and checking the quota never costs quota. Session saving, MCP servers and hooks are switched off for that process; closing stdin ends it.

The only thing the app writes is its window position, in its own preferences.

This approach has an honest cost: it depends on the CLIs' behaviour. Codex's method is documented. Claude Code labels get_usage as experimental, so a future CLI release could change its shape; the README says so. If that happens, the check fails loudly: the panel keeps the last good numbers, marks them stale and shows the error, rather than inventing a value.

The parts that were harder than they looked

The app is about 700 lines of Swift with no third-party dependencies: a small data layer (QuotaKit, unit-tested) and an AppKit/SwiftUI shell. Most of it was straightforward. A few things weren't.

Talking to a CLI without ever hanging. Both sources run through one helper that starts a process, sends one JSON line, and reads newline-delimited JSON back through a non-blocking reader that skips anything that isn't a JSON object. Every exchange has a hard 25-second deadline. When it returns, the process gets SIGTERM, then SIGKILL two seconds later if it's still alive, and the app ignores SIGPIPE so a CLI that exits early can't take it down. The tests stand in for the CLIs with tiny shell scripts — including one that deliberately ignores SIGTERM — to prove that the kill path really is bounded. A menu-bar app that leaks a zombie claude process every five minutes would be a bad trade for saving a few keystrokes.

Why Claude refreshes less often. Each Claude check starts a full Claude Code process, which is not free, so Claude refreshes every five minutes instead of every minute. For windows measured in hours and days, a few minutes of lag is fine.

The environment-variable trap. Plan limits only exist for plan sign-ins. If the Claude process inherits API-key or gateway settings — ANTHROPIC_*, most CLAUDE_CODE_* variables, or CLAUDECODE, which is set in any shell opened inside Claude Code — the CLI reports that plan limits are unavailable. That one is easy to hit by accident, since the natural place to test a tool like this is a terminal inside the very agent it's measuring. So the app strips those variables from the Claude process's environment, keeping only CLAUDE_CODE_OAUTH_TOKEN.

A floating window that ignores the mouse. The panel is a borderless, non-activating NSPanel at floating level that joins all Spaces — the right recipe for "visible but never steals focus". It is also the recipe for a window that doesn't respond to dragging, or swallows the first click when it's inactive. Getting title dragging, first-click behaviour and the two title-bar buttons all working took three overlapping event paths, and the architecture notes now carry a warning to re-test all three before anyone "simplifies" them.

A gauge that follows the menu bar. The menu-bar gauge is an image drawn by a closure every time it's displayed, so its label colour tracks a light or dark menu bar instead of being frozen at whatever it was when the app launched.

Trying it

Quota Float needs macOS 13 or later (Apple silicon or Intel), plus whichever of the two CLIs you use, signed in with your plan: codex login for Codex, claude auth login for Claude Code. Either one alone works; a service that isn't set up shows a short explanation instead of numbers.

Grab QuotaFloat-1.0.0.zip from the latest release, unzip it and move Quota Float.app to Applications. Release builds are ad-hoc signed, not notarized, so macOS will block the first launch: right-click the app and choose Open, or clear the quarantine flag:

xattr -dr com.apple.quarantine "/Applications/Quota Float.app"

Add it to System Settings → General → Login Items if you want it there from boot. There's also a no-window mode that prints the current numbers in a terminal:

"/Applications/Quota Float.app/Contents/MacOS/QuotaFloat" --check

One thing to know: the CLIs' sign-ins can differ from the desktop apps', so the numbers are for whichever account each CLI is logged in to. And for the record, it's an independent project, not affiliated with or endorsed by OpenAI or Anthropic.

What's next

It's version 1.0.0 and it already did its job: I no longer stop to check, because the answer is in the corner of my eye. The notes list a few small things I'd still like — relative "resets in 2 h 10 min" countdowns, showing how old stale data is, a reset-position item for when a saved position ends up on a disconnected display, and settings for per-service visibility and refresh intervals.

The code is MIT-licensed on GitHub. If you run two coding agents and catch yourself typing /usage more often than you'd like to admit, it might save you some of the same small interruptions.
